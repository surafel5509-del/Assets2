# Shipped Games

Four complete games built on the engine, each with its own textures, animations and
UI. They are **data, not code**: a `game.json` declaring metadata and asset
references, `scenes/*.scene.json`, and `scripts/*.js`. `GameLibrary` materialises
one into a real project, importing its art from the offline asset store.

| | Directory | Title | Genre | Assets | Packs | Scripts |
|---|---|---|---|---|---|---|
| 1 | `01_topdown_rpg/` | Emberfall | 2D top-down RPG / adventure | 35 | 8 | 7 |
| 2 | `02_fighting_2d/` | Blade & Bulwark | 2D fighting | 26 | 5 | 6 |
| 3 | `03_action_3d/` | Hollow Ridge | 3D action-adventure | 38 | 5 | 7 |
| 4 | `04_runner_3d/` | Neon Overdrive | 3D endless runner / racer | 20 | 6 | 7 |

`index.json` is the ordered list `GameLibrary` reads. It is **generated** by
`tools/build_asset_store.py`, so it cannot drift from what is on disk.

## Layout of a game

```
<game>/
├── game.json              id, title, genre, orientation, startScene,
│                          scripts[], controls, systems, engineNotes, assets[]
├── scenes/Main.scene.json scene graph: objects, components, transforms
├── scripts/*.js           ES5 gameplay logic (Rhino — no let/const/arrow fns)
└── README.md
```

An `assets[]` entry is `{ pack, path, as, [anim] }`: which store pack it comes
from, its path **within that pack**, the short name it lands under in the project,
and an optional animation grid. The short name matters because scenes reference
`hero_walk.png`, never a pack-relative path, and several packs contain files with
colliding basenames.

## Adding a game

1. Create `games/<NN_slug>/` with `game.json`, a scene, and scripts.
2. Set `"id"` to **exactly** the directory name — `GameLibrary` resolves
   `games/<id>/...` from it, and the generator warns on a mismatch.
3. Run the validator until it passes:

```bash
python3 tools/validate_games.py <slug>
```

No Kotlin changes are needed. The Gradle `stageGameLibrary` task picks the
directory up, and `index.json` is regenerated by the build tool.

## Validation

```bash
python3 tools/validate_games.py              # all games → 2 484 checks, 0 errors
node tools/run_games.js                      # executes all 27 scripts headlessly
python3 tools/validate_games.py runner       # filter by slug substring
```

The validator checks every asset reference against the store manifest *and* that
pack's licence, checks scene JSON against the engine's 14-key component registry,
verifies parent references, syntax-checks every script with `node --check`, and
confirms every `audio.play()` target is a declared asset. It also rejects the
platformer and space-shooter genres, which are explicitly out of scope.

See [../docs/07-GAMES.md](../docs/07-GAMES.md) for what it has caught.

## Status

The games are validated for internal consistency and asset existence. They are
**not run** — there is no Android runtime in this environment, so nothing here
confirms that they play correctly or feel good. That gap is stated rather than
papered over.
