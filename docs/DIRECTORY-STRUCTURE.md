## What is generated and what is committed

| Path | Generated by | Committed |
|---|---|---|
| `app/src/main/assets/store/store_manifest.json` | `build_asset_store.py` | **yes** — it is the catalogue and the validation contract |
| `app/src/main/assets/store/pack_map.txt` | `build_asset_store.py` | **yes** — Gradle reads it |
| `docs/asset-store/CATALOG.md` | `build_asset_store.py` | **yes** — human-readable index |
| `games/index.json` | `build_asset_store.py` | **yes** — read at runtime by `GameLibrary` |
| `build/generated/storeAssets/*.zip` | Gradle `stageStoreAssets` | no |
| `build/generated/gameLibrary/` | Gradle `stageGameLibrary` | no |
| `native/**/*.o`, `*.d` | `make` | no |

## Conventions

**A project on disk** (`filesDir/projects/<name>/`) is:

```
project.json              { name, engine, startScene, created, orientation }
scenes/<Name>.scene.json  { name, gravity*, ambient, fog*, nextId, objects[] }
assets/*                  flat; images, audio, models, .js, .anim, .bp, .glsl
```

Assets are **flat by design**. The store's packs have deep, inconsistent directory
structures, and flattening on import is what lets a scene reference
`hero_walk.png` without knowing which pack it came from. Collisions are resolved by
`Project.uniqueAssetName`, which appends `_1`, `_2`, …

**Scene object shape:**

```json
{ "id": 5, "name": "Hero", "tag": "Player", "active": true, "order": 10,
  "x": 0, "y": 0, "rotation": 0, "scaleX": 1.8, "scaleY": 1.8,
  "z": 0, "rotX": 0, "rotY": 0, "scaleZ": 1.8, "parent": 1,
  "components": [ { "type": "SpriteRenderer", "enabled": true, "Texture": "..." } ] }
```

Component `type` values are the 14 `ComponentRegistry` keys. Component properties
serialise under their Inspector **display names**, not their Kotlin field names —
which is why scene validation must read the registry rather than the classes.
Unknown component types are skipped silently, so an older scene still loads in a
newer editor.
